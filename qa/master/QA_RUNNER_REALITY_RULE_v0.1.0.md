# Devnet Master QA — additive runner reality gate v0.1.0
**Status: QA candidate, NOT release approval.** 2026-10-31.

This extends—not replaces—the preserved Devnet Master QA v0.3.8 baseline, its GitHub-first order, signed operator checklist, job-specific requirements, deterministic evidence gate, gaming controls, and the rule to execute 100% of applicable checks FRESH on EVERY revision. No prior PASS may be inherited. The QA runner, installer, updater and evidence collector count as software and require full applicable testing too.

## Mandatory runner acceptance

1. **Real-tool compatibility.** Execute the EXACT new/modified runner against actual dependency CLI/API output inside the genuine target OS/VM BEFORE relying on it for application acceptance. Record command argv, resolved binary path, binary SHA256, exit code, raw stdout/stderr, version, environment and timestamp. Bind the evidence to exact candidate ZIP SHA256, runner SHA256, job ID and revision. Mocks, simulated output and parser-only unit tests may supplement but NEVER replace live execution.
2. **Version and output matrix.** Test each parsed tool output against the tool's genuine current native formatting and boundaries. The real CachyOS output `opencode v2.2.4` must pass the OpenCode major-2 check, as must `2.2.4` and `v2.2.4`. Wrong major, malformed/foreign output, nonzero exit, missing binary, unexpected prefix, altered command, timeout, or incompatible tool version must fail closed. Test whitespace, warnings, stderr and suffixes where they occur in real output. Do not loosen validation to accept arbitrary text.
3. **Independent runner evidence.** A separate deterministic verifier must check the real executable identity, raw outcome, exact revision/artefact SHA256, complete scope, freshness, and tampering/negative cases. A runner's own PASS is not approval. Any missing, altered, stale, untrusted, inherited or simulated result must remain FAIL/BLOCKED/NOT_TESTED.
4. **ALL tests again on EVERY change.** Every changed runner/parser/dependency/configuration requires all applicable fresh GitHub-hosted tests FIRST; local CachyOS QA VM SECOND; authorised host tests THIRD. Rerun even previously passing checks. Cover install, upgrade, rollback, real runtime, sandbox/privacy/permissions, genuine GUI/tray when applicable, file writes, gaming guard and recovery, 9B/30B live switching and idle unloading when applicable. Never convert a limited unit test result into full acceptance.
5. **Prerequisites are blockers.** Missing `opencode`/`ollama`, package-mirror errors, sudo permission issues, unsupported versions, or unavailable GUI are blockers and cannot be bypassed with fake executables or inherited evidence. Fix the prerequisite safely and rerun the full stage.
6. **Signed checklist protection.** Add the check IDs `runner_real_dependency_output`, `runner_negative_contracts`, `runner_independent_evidence` to every signed job checklist for which runner validation is applicable. No altering or reducing the existing operator-approved checklist without renewed authorisation/signature. The independently protected Master QA stage/signing service remains authoritative. `release_approved=false` until all job-specific checks, signatures and final user acceptance are complete.
7. **Change control.** Preserve original baseline bytes and real evidence. Version this extension as a new QA candidate; perform GitHub-first tests before activating it locally. Never claim the existing immutable baseline/deployed runner was rewritten merely because this draft policy exists.

## Incident record / permanent regression

On 31 October 2026, Devnet Safe AI v0.1.2 local Master QA r2 rejected valid native OpenCode output `opencode v2.2.4` because the runner only recognised bare numeric versions. Its 30 unit regressions passed but the real VM stage was blocked. This was a defect in the QA runner, not evidence that the application was broken. Runner r3 changed the parser; its live VM/host gates remain unverified until executed.

The associated executable `runner_reality_gate.py` captures real OpenCode CLI evidence and checks it again, bound to runner/candidate hashes. Its local and GitHub unit tests remain **development-only** until the true VM and independently signed Master QA acceptance are proven. No automatic release approval.
